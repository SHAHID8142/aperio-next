Aperio Next slash-command entry point (thin wrapper; the full protocol lives
in the `aperio-next` skill).

1. Let `PROJECT` be the argument the user passed, else the current workspace
   root. Never guess a parent directory.
2. Use the verified engine path below (not a bare `aperio`, which may resolve
   to a different install). Confirm it once with
   `$APERIO_CLI core-identity --json` — it must print
   `"product": "aperio-next"`.
3. Run the canonical read-only entry point:

   ```
   $APERIO_CLI next "$$PROJECT" --json
   ```

4. The JSON document names the project state and exactly one next action.
   Follow that action. It never initializes or modifies anything by itself:
   - New/unmanaged project → walk the user through onboarding; nothing is
     written until the user explicitly confirms initialization.
   - Aperio-managed project → load `$APERIO_CLI memory "$$PROJECT"` and
     `$APERIO_CLI work-status "$$PROJECT"`, run
     `$APERIO_CLI recover "$$PROJECT"` if the last session was interrupted,
     and resume inside the approved plan.
5. If the engine path is missing or `core-identity` reports a different
   product, do not continue: re-install with `npx aperio-next install` (or the
   documented local artifact) and stop.
